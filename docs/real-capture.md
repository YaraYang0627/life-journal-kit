# 可选真实飞书采集与 macOS 定时运行

默认关闭。需要用户已登录的 lark-cli，以及用户明确指定的单聊、机器人和工作总结标记。不要提交账号配置、凭证、采集数据或运行日志。

## 私有配置
配置与数据必须放在源码之外，建议非同步目录、仅本人可读。配置字段：enabled（必须为 true）、chat_id、sender_open_bot_id、primary_marker、cli_path（绝对路径）、timezone。配置不存 token，凭证由现有 lark-cli 管理。新用户需要自行完成授权；本机连接通过不代表其他账号拥有相同权限。

```sh
python3 scripts/lark_capture.py --data /absolute/private/data --config /absolute/private/settings.json --date 2026-10-16
```
先用 journal.py init 初始化真实数据目录，不能使用 demo 目录。读取指定日、指定单聊、指定机器人的总结；优先专用标记，缺失时匹配“每日回顾”。只接受完整分页，最多 10 页；不读取附件或其他聊天。真实 CLI 返回的本地时间按配置时区解释，子进程也设置相同时区。

正文作为“工作总结（二次来源，待本人核对）”存入本地收件箱与初稿，不自动拆成事实或情绪。常见密钥格式自动遮盖，但这不是完整脱敏器，数据仍按敏感资料处理。记录 hash 用于去重，源消息变化进入人工核对，不静默覆盖。来源状态仅在初稿保存并验证后提交。无总结或授权失效会输出固定状态码，不输出原消息或 CLI 错误正文。

边界：只处理消息创建日；跨午夜新发送的前一天总结不会自动归到前一天。汇总标题的 ISO 日期用于排除明显错日，最终仍需人工核对。已有终稿不改动。此脚本不调用 AI、不自动生成最终日记、月报或地图。

## 定时试跑
```sh
python3 scripts/scheduled_capture.py --data /absolute/private/data --config /absolute/private/settings.json --start 2026-10-18 --end 2026-10-18
```
执行范围最多 32 个自然日；每次检查昨天，22:30 后同时检查今天，均受 start/end 限定。长时间离线只补昨天，更早缺口需手动采集。重复读取用于发现编辑和迟到消息；单次失败等下次系统触发重试。

macOS LaunchAgent 使用绝对路径，StartCalendarInterval 可设 22:30、23:00、08:00；使用 caffeinate -i 仅在采集期间防止空闲睡眠。程序与私有数据建议放本地非同步目录。LaunchAgent 本身不负责唤醒电脑，需另设 pmset 单次 wake；不要覆盖已有 repeat 计划或使用 cancelall。启用系统配置前先展示具体日期、范围和卸载方法。

试跑需开机、已登录、网络可用，建议接电。FileVault 开启时，关机后启动需要人工登录；合盖和具体硬件表现必须实测。StartCalendarInterval 在睡眠后恢复时可补执行，但不保证电脑在计划时刻已醒。范围结束后不再读取飞书，但已安装任务仍需卸载以停止空启动。
