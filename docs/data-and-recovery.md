# 数据格式与恢复

## 初稿可编辑范围

`draft` 返回 JSON 文件。AI 可修改 `title`、`sections[].heading`、`sections[].paragraphs[].text`；每段 `sources` 是收件箱素材 ID 数组。顶层 `sources` 保存原始素材快照，`fingerprint` 校验整批素材是否变化，不能为了绕过检查而修改它们。

`finalize` 要求所有来源至少引用一次、每段都有有效来源、目标日期一致。此检查不等于语义真实性审查。素材中不适合记录的部分应在整理输入前由本人决定；基础版没有删除素材命令。

日记文件采用 JSON 保存结构与来源，同时导出 Markdown。两者不一致时停止构建。基础版不支持静默修改终稿；如需修订，先保留原文与变更依据，等待正式版本化修订功能或由维护者设计具体修订步骤。

## 月度回顾

每次 review 产生新的 `vNNN.json`。`month/count/through/fingerprint` 由工具计算，编辑时保留。每个段落必须有 `date`、`text` 和 `sources`，引用该日期的已确认素材。跨日变化拆成多个日期段落。原话汇编可直接阅读；有主题的回顾需要 AI 或用户整理。

地图使用最新一版回顾。若其 fingerprint 不对应当前月终稿集合，隐藏回顾内容并显示需要更新；历史版本保留。缺失日记不自动补齐。

## 常见问题

| 提示或现象 | 如何处理 |
|---|---|
| 数据必须放在源码之外 | 换一个与源码平级的目录；不能把真实日记放入仓库 |
| 已初始化或目录非空 | 直接使用已有数据命令；演示选择新的空目录，不覆盖旧目录 |
| 没有素材 | 先 add 指定日期的片段；不生成空日记 |
| 初稿与素材不一致 | 先 draft 合并新的素材，再审阅和确认 |
| 已有终稿 | 不覆盖；晚到素材仍留在 inbox，本版不自动修订 |
| 终稿 Markdown 与快照不一致 | 暂停生成，核对修改依据；不要用程序随意覆盖任一版本 |
| 找不到 Python | 安装官方 Python 3.9+ 后再按教程运行；工具不会自动安装系统依赖 |
| 端口占用 | serve 加 --port 4319；也可以直接浏览生成的 HTML |
| 页面没更新 | build 后刷新；serve 不自动监听文件 |
| `.pending-*` 目录 | 属于尚未整体发布的临时输出，读者忽略它；确认有效终稿与初稿后才人工处理，不自动删除 |
| 终稿已保存但初稿归档失败 | 先核对 days 下两份终稿完整一致，再将 drafts 中对应初稿移入 draft-history；不重跑覆盖终稿 |

所有写入使用临时文件加原子替换。终稿的两个文件先写进临时目录，再整体发布。它提供文件操作级故障保护，不承诺断电后的磁盘级持久性，也不替代备份。CLI 使用本机文件锁，AI 直接编辑 JSON 时不要同时运行其他写入操作；网络盘跨设备锁未验证。

源码更新不应改动用户目录。备份、同步与加密由用户选择；本工具当前没有加密存储功能。导出的地图包含来源原文，应与日记同等保护。
