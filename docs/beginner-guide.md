## 二、先判断自己能不能用

准备一台 Mac、浏览器，以及能登录并操作本地项目的 Codex 环境。程序需要 Python 3.9 或以上，可以先让 Codex 检查；缺少时按它说明的官方安装方法处理，不要假设所有 Mac 都已经装好。

这不是手机 App，也不是打开 GitHub 网页就能在线写日记的网站。GitHub 是下载和存放工具的地方；工具与日记运行在自己的电脑上。当前不建议没有 Mac 的观众照抄本教程，Windows 原生运行暂不支持。

不必先连接飞书，不必先配置定时器，不必自行申请模型 API key。通过 Codex 整理时仍需可用账号和额度。

官方桌面应用说明：https://learn.chatgpt.com/docs/app
官方技能说明：https://learn.chatgpt.com/docs/build-skills
不同版本的按钮名称可能不同；以“打开本地文件夹／添加项目”的含义为准，不能把文件仅作为聊天附件上传。

## 三、第一次体验：先看虚构地图

### 第 1 步：下载

打开首版下载页，在 Assets／资源下点 Source code (zip)／源代码（zip）。不需要先 Star、Fork 或创建仓库，也不需要把自己的日记上传到 GitHub。

### 第 2 步：解压

双击下载的 zip。打开解压文件夹，应该能看到 README.md、scripts、viewer、examples 等。

保留整个文件夹。不要只复制 SKILL.md，也不要只打开某个 Python 文件。

### 第 3 步：让 Codex 打开这个文件夹

在桌面应用中选择 Codex，添加本地项目或打开文件夹，选择刚解压、包含 README.md 的那个文件夹。在这个项目里新建对话。

### 第 4 步：复制下面这段话

```text
这是 Life Journal Kit 项目。请先读取当前项目的 AGENTS.md 和 README.md，检查 Python 版本是否至少为 3.9。
我第一次使用，请只运行项目自带的虚构演示，不读取我的私人文件，不接入飞书，不设置定时任务。
请在源码文件夹旁选择一个不存在的新目录 journal-demo；如已存在，换用新的编号目录，不覆盖旧数据。
按照 README 执行 demo 和 serve，打开本地生活地图，并告诉我以后怎样重新打开和停止预览。
如果缺少运行条件，请用小白能理解的方式说明具体缺什么，不要直接安装全局依赖或修改系统设置。
```

成功标志：浏览器显示虚构日记地图，能切换月份、点开某一天并查看来源。没有看到地图时，不要急着输入真实日记，先解决报错。

这一阶段的数据都是演示，不是你自己的经历。预览服务关闭或电脑重启后，需要重新启动；这不表示日记文件被删除。

## 四、开始自己的第一篇日记

### 第 1 步：建独立的数据目录

继续在同一个 Codex 项目中发：

```text
我想开始自己的日记。请读取 .agents/skills/life-journal/SKILL.md 并按这个 Skill 执行。
在源码文件夹旁创建一个新的 my-journal 数据目录，使用 Asia/Shanghai 时区；如果已存在，请先检查是否是我的现有日记目录，不要覆盖或重新初始化。
真实记录与 journal-demo 演示完全分开。告诉我日记保存的绝对路径，并确认是否位于同步盘；如果是同步盘，先让我选择是否改用非同步位置。
本次只建立目录，不生成日记、不读取其他资料。
```

如果不在中国时区，把 Asia/Shanghai 换成自己的时区。不清楚时告诉 Codex 所在城市，让它先确认时区。

### 第 2 步：给出日期和生活片段

把方括号替换成真实内容后再发送：

```text
使用 life-journal，继续使用刚才的 my-journal 数据目录。
请记录 [YYYY-MM-DD] 的日记，素材如下：
今天发生的事：[自己填写]
我明确想记下的感受：[自己填写；没有就说没有]
还没完成或只是计划的事：[自己填写]
请先给我看初稿，不要自动定稿，不补写我没说过的细节。
```

不用写成作文。几句话也可以；某项没有就省略。下班后的见面、散步、购物、家庭交流等线下经历，需要自己补充。工具不会自动知道这些事情。

### 第 3 步：核对、修改，再确认

先看日期、人物、事情有没有记错，计划有没有被误写成已经完成，感受是不是自己的原话。

有错就直接说：

```text
这里要改：那件事只是计划，还没有完成。请修改初稿，其他已核对内容保留。
```

核对无误后再发：

```text
可以定稿。请按项目规则保存今天的终稿，更新生活地图，并打开给我看。
```

成功标志：有当天的终稿文件；更新地图后能点开这一天。只有初稿而没定稿时，地图里暂时没有这一天是正常的。

## 五、以后每天怎么用

继续打开同一个项目和同一个数据目录，发“记 [具体日期] 的日记”，补充素材，核对后说“可以定稿，更新地图”。不要每天重新下载工具或新建数据目录。

跨过午夜补昨天时，把昨天的日期写清楚。已经定稿的旧日记需要订正时，说明日期和修改依据；当前版本不会直接覆盖旧终稿。

月底发送：

```text
使用 life-journal，继续使用我的 my-journal 数据目录。
请根据 [YYYY-MM] 已确认的日记生成月度回顾，保留来源，不推断没有记录的日子，也不编造情绪或成果。
先展示回顾供我检查，并按项目规则更新地图。
```

月度回顾需要发起这个请求；基础版不会到月底自动生成。日记地图也是已保存内容的快照，更新后需要重建／刷新。

## 六、飞书与自动化什么时候接

先连续完成几次“补充素材—初稿—确认—地图”，再接飞书与定时运行。

当前飞书功能只采集自己授权、指定单聊和机器人发出的工作总结，并非自动读取公司所有聊天、会议和文档。别人需要配置自己的账号和权限，不能复用作者的授权。没有当天总结就报告素材不足；不会用别人的或其他日期的记录代替。

macOS 单次睡眠唤醒与后台读取已经在作者设备验证，但长期运行与其他电脑尚未验收。每位使用者都应先做短时试跑。定时采集只产生待核对素材初稿，不会替本人确认最终日记。

接入说明：https://github.com/YaraYang0627/life-journal-kit/blob/main/docs/real-capture.md

## 七、视频演示脚本（约 90—120 秒，时长为估计）

| 顺序 | 画面 | 可以直接说的口播 |
| --- | --- | --- |
| 开头 | 虚构地图月份总览，标注“虚构演示” | 你还记得上个月的某一天，自己做过什么吗？我把自己用 AI 写日记的方法，整理成了一个开源工具。 |
| 看结果 | 点开某一天，再打开月度回顾 | 平时把经历记下来，确认后就能在这里按日期回看，还能把一个月的记录整理成回顾。现在展示的是虚构示例。 |
| 下载 | GitHub 首页与版本下载位置 | 链接放在简介里。下载这个压缩包，解压，再用 Codex 打开整个文件夹。当前先推荐 Mac 用户体验。 |
| 跑演示 | 粘贴教程里的演示提示词 | 不用先接飞书，先复制这段话，让 AI 带你跑一遍演示。缺少环境时，先按提示补齐。 |
| 记一篇 | 输入一段明确标注为虚构的素材 | 正式使用时，给出具体日期和当天经历。工作之外的生活也要自己补充，它不会自动知道。 |
| 核对 | 展示初稿，把计划改正为未完成 | 我会先看初稿，尤其检查计划有没有被写成已经做完。没问题，再说“可以定稿”。 |
| 收尾 | 更新地图，展示项目链接 | 这样，每天的片段就能慢慢积累下来。首版已经公开，工具免费开源，AI 服务另计。先试基础流程，飞书和定时功能后面再接。 |

录像时统一使用虚构日期与素材，并在画面持续标注“虚构演示”；不要录私人日记地图、真实飞书聊天、登录弹窗或个人目录路径。口播表达的是实际步骤，不保证新用户在固定几分钟内一定完成。

建议封面文案：我把 AI 日记方法开源了
备选标题：每天说几句，把生活慢慢记下来｜AI 日记与生活地图
视频收尾：下载和教程都在简介，先体验虚构示例，再开始自己的第一篇。

| 报错应该发什么？ | 提供操作步骤和错误提示，隐藏私人路径与正文；不要贴真实日记、飞书消息或密钥。 |
| 私密吗？ | 文件保存在本地，但同步盘可能同步，云端 AI 可能处理你提交的素材。不要称为“绝对不联网”或“永不上传”。 |
